Generate implementation plan for Phase 4 covering:

## Architecture Decisions

### AD-4.1: Containerization Strategy
- Use multi-stage Docker builds
- Frontend: Build stage + Runtime stage with nginx
- Backend: Dependencies stage + Application stage
- Base images: node:20-alpine (frontend), python:3.13-slim (backend)

### AD-4.2: Kubernetes Architecture
- Single namespace: todo-app
- Frontend Deployment: 2 replicas
- Backend Deployment: 2 replicas
- Frontend Service: ClusterIP
- Backend Service: ClusterIP
- Ingress: nginx-ingress for external access
- ConfigMaps: app-config (non-sensitive)
- Secrets: db-credentials, api-keys

### AD-4.3: Helm Chart Structure
```
helm-charts/
├── todo-app/                 # Umbrella chart
│   ├── Chart.yaml
│   ├── values.yaml

│       │   ├── service.yaml

│       │   └── secret.yaml
│       └── ingress.yaml
```

### AD-4.4: Image Registry Strategy
- Development: Minikube local registry (eval $(minikube docker-env))
- Optional: Docker Hub for sharing (docker.io/username/todo-frontend:v1)

### AD-4.5: Database Strategy
- Continue using Neon Serverless PostgreSQL (external)
- Connection via Kubernetes Secret
- Alternative: Local PostgreSQL in StatefulSet (for offline dev)

### AD-4.6: Service Exposure Strategy
- Development: Minikube Ingress with /etc/hosts entry
- Alternative: kubectl port-forward for quick testing
- Frontend: http://todo.local/
- Backend API: http://todo.local/api/
